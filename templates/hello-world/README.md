# hello-world(自動デプロイの入口)

**CI/CD(GitHub Actions での自動デプロイ)をする場合も、このテンプレートから始めてください。**

最初に置く、仮のウェブアプリ(`traefik/whoami`)です。自分のアプリを、GitHub から自動でデプロイするための、出発点になります。

## 作ると何が起きるか

- deploy を 1 つ(ポート 80)、Service、公開の ingress(URL)を作ります。
- 公開の URL を開くと、**ホスト名と、受け取ったヘッダーの一覧**が出ます。これが出れば、公開までの道は、つながっています。このページは、仮のものです。

## 自分のアプリに置き換える

1. 作ったあと、deploy を開き、**概要** タブの **自動デプロイ(webhook)** を開きます。
2. 画面の案内に従って、GitHub Actions の YAML を作ります(**Railpack** か **Dockerfile** を選べます)。
3. その YAML を、アプリのリポジトリの `.github/workflows/` に置いて、push します。
4. 画面の案内の **Secrets**(`LAUNCHS_URL`、`LAUNCHS_TOKEN`)を、GitHub のリポジトリに登録します。
5. push するたびに、イメージが作られ、この deploy のイメージが、**自動で入れ替わります**。入れ替えの記録は、deploy の概要の **イメージ** の **更新履歴** で見られます。

## つまずきやすいところ

- **ghcr.io のイメージは、最初は非公開**です。GitHub のパッケージの設定で、**Public** にしてください(しないと、クラスターが、イメージを取れません)。
- アプリのポートが **80 でない**ときは、deploy の **Service** と、ingress の **ルール** の、ポートを直してください。
- アプリが、環境変数や設定ファイルを必要とするときは、deploy の **起動設定** と **ConfigMap** で足せます。

## 構成と注意

deploy を 1 つ、Service、公開の ingress を作ります。イメージは、あとから、自分のイメージに置き換えます。
